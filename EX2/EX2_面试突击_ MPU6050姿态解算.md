## 一、实验核心原理（大白话版）

### 1.1 这个实验到底在测什么？
小车要站起来，必须先知道「我现在往前倾了多少度、往后仰了多少度」。这个角度叫 **Pitch（俯仰角）**。MPU6050 是一个六轴传感器，里面有：
- **三轴加速度计**：感受重力方向和运动加速度；
- **三轴陀螺仪**：感受绕三个轴转动的角速度。

单靠加速度计算角度：静止时准，但一晃动就乱（因为它把运动加速度也当成重力了）。
单靠陀螺仪积分算角度：短时准，但时间一长会漂移（零偏积分会越积越大）。

所以实验的核心就是 **把两者「融合」起来**，得到又准又稳的 Pitch。代码里实现了三种方法：
1. **加速度角**（只信加速度计，做参考/对照）；
2. **互补滤波**（短时间信陀螺仪，长时间信加速度计，加权融合）；
3. **一维卡尔曼滤波**（用数学模型同时估计角度和陀螺仪零偏）；
4. **DMP**（MPU6050 内部运动处理器直接输出融合后的角度）。

### 1.2 姿态解算为什么选 Pitch，不选 Roll/Yaw？
因为小车前后倾倒是我们最关心的运动。实验中发现前后倾主要体现在 MPU6050 的 **ay（Y 轴加速度）** 和 **gx（X 轴角速度）** 上，所以把 Pitch 定义为 **绕 X 轴的旋转角**。代码里 `PITCH_SIGN = 1.0f`，约定 **前倾为负、后仰为正**。

### 1.3 三种解算方法一句话总结

| 方法 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|
| 加速度角 | 无漂移、计算极简 | 噪声大、受线加速度干扰 | 静态或低速参考 |
| 互补滤波 | 计算量小、实时性好 | 参数固定，对零偏修正弱 | 资源有限的嵌入式实时控制 |
| 卡尔曼滤波 | 能估计零偏、长期漂移小 | 计算稍大、参数需调 | 需要更严格噪声建模 |
| DMP | 最平滑、内部融合 | 输出频率低（~12 Hz）、动态响应慢 | 快速获取平滑姿态 |

### 1.4 单位换算要会背
- 加速度 raw → g：`raw / 16384`（量程 ±2g，由 `MPU_REG_ACCEL_CONFIG = 0x00` 配置）。
- 陀螺仪 raw → °/s：`raw / 16.4`（量程 ±2000°/s，由 `MPU_REG_GYRO_CONFIG = 0x18` 配置）。
- g → m/s²：再乘以 `9.80665`。
- 角度：rad → deg 乘以 `57.2957795f`（即 `180/π`）。

## 二、关键代码逻辑（必须知道的代码位置）

> 以下文件、函数、参数名都要能说出来。

### 2.1 工程与主循环
- **主文件**：`EX2/Users/mpu6050_lab.c`（注意：这个文件里直接写了 `main()`，不是 `Users/main.c`）。
- **Keil 工程**：`Projects/MDK-ARM/atk_f103.uvprojx`。
- **主循环周期**：默认 `DEFAULT_PERIOD_MS = 20`，即 50 Hz；可通过 `RATE 20/50/100` 改成 50 ms/20 ms/10 ms。

`main()` 里做的事情（按顺序）：
1. `HAL_Init()`、`sys_stm32_clock_init(RCC_PLL_MUL9)`：系统时钟 72 MHz；
2. `usart_init(115200)`：串口 115200-8-N-1；
3. `mpu6050_interface_iic_init()`：软件 I2C 初始化；
4. `mpu_basic_init()`：配置 MPU6050 寄存器，读取 `WHO_AM_I`；
5. `init_dmp()`：初始化 DMP；
6. `calibrate_static()`：静止校准；
7. 进入 `while(1)`：每 20 ms 读取一次数据、更新三种算法、输出 CSV。

### 2.2 I2C 与 MPU6050 初始化
- **软件 I2C 引脚**：PB14 = SCL，PB15 = SDA，PB9 = INT。
- **MPU6050 写地址**：`MPU_ADDR_WRITE = 0xD0`。
- **WHO_AM_I**：`MPU_REG_WHO_AM_I = 0x75`，读出来是 `0x68`。

`mpu_basic_init()` 寄存器配置（能说出大意即可）：
```c
write_reg(MPU_REG_PWR_MGMT_1, 0x80);  // 设备复位
delay_ms(100);
write_reg(MPU_REG_PWR_MGMT_1, 0x01);  // 时钟源设为 X 轴陀螺仪
write_reg(MPU_REG_SMPLRT_DIV, 0x04);  // 采样率分频
write_reg(MPU_REG_CONFIG, 0x03);      // 低通滤波配置
write_reg(MPU_REG_GYRO_CONFIG, 0x18); // 陀螺仪 ±2000 dps
write_reg(MPU_REG_ACCEL_CONFIG, 0x00);// 加速度计 ±2g
write_reg(MPU_REG_INT_PIN_CFG, 0x10);
write_reg(MPU_REG_INT_ENABLE, 0x01);  // 使能数据就绪中断
```

### 2.3 原始数据读取与转换
函数：`read_raw_sample(raw_sample_t *sample)`
- 从寄存器 `MPU_REG_ACCEL_XOUT_H = 0x3B` 连续读 14 字节；
- 高字节在前、低字节在后，拼成 `int16_t`；
- 加速度除以 `16384.0f` 得到 g，陀螺仪除以 `16.4f` 得到 deg/s。

### 2.4 加速度角
函数：`compute_pitch_acc()`
```c
float denom = sqrtf(ax_g*ax_g + az_g*az_g);
return PITCH_SIGN * atan2f(ay_g, denom) * RAD_TO_DEG;
```
- 用 `ay_g` 和 `sqrt(ax²+az²)` 求 arctan；
- 这个公式来自：重力在 Y 轴的分量与水平面分量的比值；
- 分母做 `0.0001f` 保护，防止除零。

### 2.5 互补滤波
函数：`complementary_update()`
```c
const float alpha = 0.98f;
g_pitch_comp = alpha * (g_pitch_comp + gyro_x_dps * dt_s)
             + (1.0f - alpha) * pitch_acc;
```
- `alpha = 0.98`：98% 信陀螺仪积分，2% 信加速度计；
- 陀螺仪提供 **短期快速响应**，加速度计提供 **长期零偏校正**；
- `dt_s` 异常时（<=0 或 >0.2）会回退到 `g_period_ms / 1000`。

### 2.6 一维卡尔曼滤波
函数：`kalman_update()`
- 状态量：`angle`（角度）和 `bias`（陀螺仪零偏）；
- 过程噪声：`q_angle = 0.001f`，`q_bias = 0.003f`；
- 测量噪声：`r_measure = 0.5f`；
- 步骤：预测 → 更新协方差 → 计算卡尔曼增益 → 观测校正 → 更新协方差。
- 关键点：它不仅能估计角度，还能在线估计陀螺零偏，长期漂移更小。

### 2.7 DMP
函数：`init_dmp()` 和 `read_dmp()`
- 调用 `driver_mpu6050_dmp` 库；
- `read_dmp()` 从 FIFO 里读出一组数据，取最后一个 `roll_buf[len-1]` 给 `pitch_dmp`；
- **为什么用 roll_buf？** 因为代码把「前后倾」映射到了 MPU6050 的 X 轴旋转，而 DMP 原始输出里这个轴对应 roll；`PITCH_SIGN` 控制符号。
- 代码里统计 `dmp_hz`：每 1 秒窗口内读到的 DMP 样本数 / 时间。

### 2.8 静止校准
函数：`calibrate_static()`
- 采集 200 次原始数据（每次间隔 5 ms，共约 1 秒）；
- 计算陀螺仪零偏 `g_gyro_bias_x/y/z`；
- 计算加速度角均值，作为互补滤波和卡尔曼的初始角度；
- 输出 `gx_bias`、`gy_bias`、`gz_bias`、`pitch_mean`、`pitch_std`。

### 2.9 CSV 输出格式
```
A,ms,state,mode,ax_raw,ay_raw,az_raw,gx_raw,gy_raw,gz_raw,ax_g,ay_g,az_g,gx_dps,gy_dps,gz_dps,pitch_acc,pitch_dmp,pitch_comp,pitch_kalman,dmp_hz,dt_ms,status
```
- `state`：STATIC / TILT / SHAKE；
- `mode`：RAW / DMP / COMP / KALMAN / ALL；
- `status`：OK / RAW_FAIL / DMP_WAIT / DMP_FAIL。

### 2.10 串口命令（可能被问到实验怎么操作）

## 四、严格面试题分层

### L1 基础概念题（老师热身会问）

#### L1-1 MPU6050 是什么传感器？能测哪些量？
- **考点**：传感器基本功。
- **回答框架**：MPU6050 是六轴 IMU，包含三轴加速度计和三轴陀螺仪。加速度计测线加速度（包括重力分量），陀螺仪测角速度。本实验主要用它们解算俯仰角 Pitch。

#### L1-2 加速度和陀螺仪的单位分别是什么？代码里怎么换算？
- **考点**：单位换算。
- **回答框架**：加速度输出 raw 值除以 16384 得到 g（因为量程 ±2g）；陀螺仪 raw 值除以 16.4 得到 deg/s（因为量程 ±2000°/s）。代码在 `read_raw_sample()` 里完成：
  ```c
  sample->ax_g = sample->ax_raw / 16384.0f;
  sample->gx_dps = sample->gx_raw / 16.4f;
  ```

#### L1-3 为什么单靠加速度计不能算准角度？
- **考点**：传感器局限。
- **回答框架**：加速度计测的是「合加速度」。静止时合加速度就是重力，可以算倾角；但运动时还有线加速度，会把运动加速度误当成重力分量，导致角度抖动或突变。快速晃动实验中 pitch_acc 标准差达到 52° 就是证据。

#### L1-4 为什么单靠陀螺仪积分不能算准角度？
- **考点**：漂移概念。
- **回答框架**：陀螺仪输出有零偏，积分时零偏会不断累积，导致角度慢慢漂走。互补滤波和卡尔曼滤波的作用就是把加速度计的长期稳定性「拉回来」，抑制漂移。

#### L1-5 互补滤波公式是什么？alpha=0.98 是什么意思？
- **考点**：互补滤波原理。
- **回答框架**：公式在 `complementary_update()`：
  ```c
  g_pitch_comp = 0.98f * (g_pitch_comp + gyro_x * dt) + 0.02f * pitch_acc;
  ```
  意思是 98% 用陀螺仪积分（短时准确、响应快），2% 用加速度计（长期稳定、抑制漂移）。alpha 越大，越信陀螺仪，响应越快但越容易受漂移影响；alpha 越小，越信加速度计，更平滑但动态响应越慢。

### L2 代码/实现细节题（老师看你懂不懂代码）

#### L2-1 主循环多久执行一次？怎么实现的？
- **考点**：主循环时序。
- **回答框架**：默认 20 ms，即 50 Hz。代码用 `HAL_GetTick()` 做时间基准，`next_sample_ms = last_sample_ms + g_period_ms`。如果主循环被串口打印或调试器拖慢，会检测 `(now_ms - next_sample_ms) >= g_period_ms` 并重新对齐。

#### L2-2 读取 MPU6050 原始数据时，为什么从 0x3B 开始读 14 字节？
- **考点**：寄存器布局。
- **回答框架**：0x3B 是 `ACCEL_XOUT_H`，连续 14 个寄存器依次是 ax_H/L、ay_H/L、az_H/L、温度_H/L、gx_H/L、gy_H/L、gz_H/L。代码用 `read_regs(MPU_REG_ACCEL_XOUT_H, buf, 14)` 一次性读完，提高效率和时序一致性。

#### L2-3 `compute_pitch_acc()` 里为什么用 `atan2(ay_g, sqrt(ax²+az²))`？
- **考点**：姿态几何。
- **回答框架**：前后倾主要改变重力在 Y 轴的分量。`sqrt(ax²+az²)` 是重力在水平面（XZ 平面）的投影大小。`ay` 与水平投影的比值就是倾角的正切，arctan 后得到 Pitch。代码里 `PITCH_SIGN = 1.0f`，所以前倾为负、后仰为正。

#### L2-4 DMP 的输出为什么对应 `roll_buf` 而不是 `pitch_buf`？
- **考点**：坐标映射。
- **回答框架**：实验发现前后倾主要对应 MPU6050 的 ay/gx，也就是绕 X 轴的旋转。在 DMP 的输出约定里，绕 X 轴的角是 roll。所以代码做了映射：`pitch_dmp = PITCH_SIGN * roll_buf[len - 1]`。这是为了和实验的「前后倾 = Pitch」约定一致。

#### L2-5 `calibrate_static()` 做了什么？
- **考点**：校准流程。
- **回答框架**：函数在 `mpu6050_lab.c` 约 357 行。它采集 200 次数据，每次间隔 5 ms，共约 1 秒；计算陀螺仪三轴零偏 `g_gyro_bias_x/y/z`；计算加速度角均值作为初始角度，同时清零并初始化卡尔曼滤波器。后续所有算法都减去这个零偏。

#### L2-6 卡尔曼滤波的三个参数 Q_angle、Q_bias、R_measure 各代表什么？
- **考点**：卡尔曼调参。
- **回答框架**：
  - `q_angle = 0.001f`：过程噪声，角度预测的不确定度；
  - `q_bias = 0.003f`：零偏过程噪声，零偏变化的不确定度；
  - `r_measure = 0.5f`：测量噪声，加速度角测量的不确定度。
  R 越大，越不相信加速度计测量；Q_bias 越大，越允许零偏变化。

#### L2-7 CSV 里 `dmp_hz` 是怎么算出来的？
- **考点**：频率统计。
- **回答框架**：代码每 1 秒统计一次：`g_dmp_hz = (g_dmp_samples_window * 1000) / (now_ms - g_last_dmp_window_ms)`。`g_dmp_samples_window` 在 `read_dmp()` 里每成功读一次 FIFO 就加上读出的样本数 `len`。

### L3 数据/现象分析题（结合报告曲线、数据）

#### L3-1 静止状态下，四种方法的 Pitch 均值和标准差分别是多少？说明什么？
- **考点**：数据读取与解释。
- **回答框架**（报告第 4 页，CSV `MPU6050_STATIC_20260707_095424.csv` 实测）：
  | 方法 | 均值 | 标准差 |
  |---|---|---|
  | pitch_acc | 12.745° | 0.617° |
  | pitch_comp | 12.436° | 0.378° |
  | pitch_kalman | 12.742° | 0.380° |
  | pitch_dmp | 15.249° | 0.314° |
  说明：DMP 最平滑（标准差最小），但与加速度角/卡尔曼有绝对值偏移（约 2.5°），因为 DMP 内部融合和坐标映射有差异；互补和卡尔曼标准差接近，明显比纯加速度角更稳定。

#### L3-2 快速晃动时，为什么 pitch_acc 标准差高达 52°，而互补/卡尔曼只有 4° 左右？
- **考点**：融合效果。
- **回答框架**：快速晃动时加速度计测到大量线加速度，不再只是重力，所以纯加速度角会剧烈抖动，甚至出现 ±60° 以上的跳变。互补和卡尔曼引入了陀螺仪积分，对线加速度有抑制作用，所以标准差降到约 4°。这说明融合算法在动态环境下明显更可靠。

#### L3-3 倾斜状态下，互补滤波和卡尔曼都能跟随到 -55°~+58°，DMP 为什么幅值更小？
- **考点**：动态响应。
- **回答框架**：DMP 内部有更强的低通平滑，加上 FIFO 读出频率只有约 12 Hz，低于主循环 50 Hz，所以对快速倾斜的跟随会滞后、幅值会被压缩。互补滤波在主循环里 50 Hz 更新，响应更直接。

#### L3-4 你的 CSV 里有没有出现过加速度满量程？在哪类状态下？
- **考点**：数据细节。
- **回答框架**：快速晃动（SHAKE）状态下出现了约 120 行加速度满量程。说明剧烈运动时加速度超出了 ±2g 量程，这进一步解释了为什么纯加速度角在 SHAKE 状态下不可靠。

#### L3-5 三种状态下 DMP 频率都稳定在 11-12 Hz，这说明什么？
- **考点**：DMP 特性。
- **回答框架**：DMP 输出由 MPU6050 内部 FIFO 和中断驱动，不随主循环 RATE 改变而改变。它说明 DMP 是一个独立、低速但稳定的姿态源，适合平滑输出但不适合高动态实时控制。

### L4 陷阱/追问题（最容易被问倒的地方）

#### L4-1 如果小车实际往前倾，但代码输出 Pitch 为正，说明什么问题？怎么改？
- **考点**：方向极性。
- **回答框架**：说明姿态符号和实际方向相反。可以把 `PITCH_SIGN` 从 `1.0f` 改成 `-1.0f`，或者在应用层取反。本实验已经验证「前倾为负、后仰为正」。

#### L4-2 互补滤波 alpha=0.98，如果我在快速晃动场景把它改成 0.5，曲线会怎样？
- **考点**：参数影响。
- **回答框架**：alpha 变小后，加速度计权重上升到 50%，曲线会更接近加速度角，噪声会明显增大（SHAKE 时可能回到 50° 标准差量级），但响应会更快；alpha 太大会更平滑但延迟更大、更容易受陀螺漂移影响。

#### L4-3 卡尔曼滤波里 R_measure 设得很大，会发生什么？
- **考点**：卡尔曼增益。
- **回答框架**：R 越大，卡尔曼增益越小，滤波器越不相信加速度计测量，输出会更接近陀螺仪积分；短期更平滑、响应更快，但长期漂移抑制变差。

#### L4-4 DMP 输出最平滑，为什么 EX3 平衡小车最终没有直接用 DMP，而是用互补滤波？
- **考点**：前后实验关联（EX2 → EX3）。
- **回答框架**：DMP 输出频率太低（~12 Hz），而平衡小车控制周期是 10 ms（100 Hz），延迟和更新率都不够。互补滤波在主循环里实时计算，延迟小、计算量小，更适合实时 PID 控制。这是 EX2 和 EX3 衔接的关键。

#### L4-5 静止时 pitch_acc 均值约 12.7°，为什么不是 0°？
- **考点**：安装基准。
- **回答框架**：因为 MPU6050 模块在小车上的安装面不是绝对水平，存在机械安装角。这个值就是传感器的静态安装倾角，代码里的 `g_middle_angle`（EX3）或校准均值就是用来补偿这个偏置的。

#### L4-6 你的代码里 `read_dmp()` 失败时 status 变成什么？主循环会怎么处理？
- **考点**：容错处理。
- **回答框架**：如果 DMP FIFO 暂时没有数据，`read_dmp()` 返回非 0，`status` 被设为 `"DMP_WAIT"`；如果 DMP 根本没初始化成功，`status` 会被设为 `"DMP_FAIL"`。主循环不会停止，而是继续输出上一帧或 0，并标记状态，保证其他通道（加速度角、互补、卡尔曼）仍然可用。

## 五、明日答辩高频题（醒目标注）

> 以下问题被问到的概率最高，建议优先背熟。

### 🔥 高频 1：一句话概括这个实验做了什么？
**建议回答**：用 STM32 通过 I2C 读取 MPU6050 的加速度和陀螺仪原始数据，完成单位换算后，用加速度角、互补滤波、一维卡尔曼滤波和 DMP 四种方法解算俯仰角 Pitch，并在静止、倾斜、快速晃动三种状态下对比噪声、延迟和漂移。

### 🔥 高频 2：互补滤波为什么能抑制漂移？
**建议回答**：互补滤波把「陀螺仪积分」和「加速度计」按时间特性互补融合。陀螺仪适合短期积分（响应快），但长期会漂移；加速度计长期稳定但短期噪声大。通过 alpha 加权，短期主要信陀螺仪，长期被加速度计拉回来，从而抑制漂移。

### 🔥 高频 3：DMP 和你自己写的互补滤波/卡尔曼有什么区别？
**建议回答**：DMP 是 MPU6050 内部处理器，融合后通过 FIFO 输出，最平滑但频率低（约 12 Hz）；互补滤波和卡尔曼在主控里实时算，频率和主循环一样（50 Hz），响应更快，但平滑性不如 DMP。

### 🔥 高频 4：你的报告中互补滤波和卡尔曼标准差都是 0.38°，说明什么？
**建议回答**：说明在静止状态下两者平滑能力接近，都明显优于纯加速度角（0.617°）。但卡尔曼还能在线估计陀螺零偏，理论上长期漂移抑制更好，只是短时实验里还没明显体现出差距。

### 🔥 高频 5：快速晃动时 DMP 曲线为什么看起来很小很平？
**建议回答**：DMP 内部做了强平滑，加上输出频率只有 11-12 Hz，跟不上快速动作，所以幅值被压缩、相位有滞后。这既是优点（噪声小）也是缺点（动态响应慢）。

### 🔥 高频 6：姿态解算的结果在 EX3 里怎么用的？
**建议回答**：EX3 平衡小车用 MPU6050 解算出的 Pitch 作为角度环 PD 的反馈，用互补滤波（或 DMP）得到的角度误差乘以 Balance_Kp，加上角速度乘以 Balance_Kd，输出电机 PWM 让小车不倒。

## 六、刁钻追问专区（老师可能连续追问 3~4 轮）

### 追问链 1：从 I2C 到 DMP
**老师 Q1**：MPU6050 和 STM32 怎么连的？
→ **你**：PB14 接 SCL，PB15 接 SDA，PB9 接 INT，软件 I2C。

**老师 Q2**：WHO_AM_I 是多少？如果读出来不是 0x68 怎么办？
→ **你**：0x68。如果不是，先检查接线、上电、I2C 地址；如果是 0x69 说明 AD0 被拉高；如果读不出，检查总线时序或硬件连接，然后重启。

**老师 Q3**：DMP 初始化失败可能是什么原因？代码里你怎么知道的？
→ **你**：可能是 DMP 固件加载失败、FIFO 溢出或中断没配置好。代码里 `init_dmp()` 返回 0 表示失败，`BOOT` 行会打印 `DMP=0`。

**老师 Q4**：DMP 输出的是四元数还是欧拉角？
→ **你**：DMP 内部用四元数做融合，驱动库会把四元数转成欧拉角输出，代码里直接读到 `pitch_buf/roll_buf/yaw_buf`。

---

### 追问链 2：从加速度角到融合
**老师 Q1**：你的加速度角公式为什么是 atan2(ay, sqrt(ax²+az²))？
→ **你**：前后倾改变重力在 Y 轴的分量，水平面投影是 sqrt(ax²+az²)，两者比值就是 tan(θ)。

**老师 Q2**：如果小车左右倾呢？应该用什么公式？
→ **你**：左右倾对应绕 Y 轴的 Roll，应该用 atan2(ax, sqrt(ay²+az²))。本实验只关心前后倾，所以用 Pitch。

**老师 Q3**：互补滤波里为什么是 0.98 和 0.02，而不是 0.5 和 0.5？
→ **你**：因为陀螺仪短期可靠，加速度计长期可靠。0.98 保证短期跟随陀螺仪的快速变化，0.02 让长期慢慢向加速度计收敛。0.5 会让加速度噪声大量进入，动态时抖动变大。

**老师 Q4**：卡尔曼滤波和互补滤波的本质区别是什么？
→ **你**：互补滤波是固定权重融合；卡尔曼滤波根据模型和测量噪声动态计算最优增益，还能估计陀螺零偏，长期漂移更小。

### 追问链 3：从数据到应用
**老师 Q1**：静止时 DMP 均值 15.25°，互补滤波 12.44°，卡尔曼 12.74°，加速度角 12.75°，为什么 DMP 偏了这么多？
→ **你**：DMP 内部有自己的坐标定义和融合算法，可能把安装角也做了某种归一化，或者 roll/pitch 映射和代码里的约定不完全一致。代码为了统一，把 DMP 的 roll 输出映射给 pitch_dmp。

**老师 Q2**：这个偏移对实际平衡小车控制有没有影响？
→ **你**：没有本质影响，因为 PID 控制看的是相对平衡点的角度误差。只要在控制程序里把「机械中值」标定好，绝对值偏多少没关系。EX3 里用 `CAL` 命令把当前角度设为中值 `g_middle_angle`。

**老师 Q3**：既然 DMP 更平滑，为什么不直接用 DMP 做平衡控制？
→ **你**：DMP 输出频率只有 12 Hz，而平衡小车控制周期 10 ms（100 Hz），延迟和更新率都不够；互补滤波在主循环里 50-100 Hz 实时算，更适合 PID。

**老师 Q4**：如果让你改进这个实验，你会做什么？
→ **你**：可以提高采样率到 100 Hz 并比较效果；或者用温度补偿校准陀螺零偏；也可以尝试二维卡尔曼或 Madgwick/Mahony 算法做全姿态解算。
