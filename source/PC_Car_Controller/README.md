# WHEELTEC 平衡小车 —— PC 控制终端（对应固件蓝牙控制部分）

在 PC 上模拟原版手机蓝牙 APP 的遥控指令，通过串口直连（USB 转 TTL 接到小车
USART3，或用 PC 蓝牙 SPP 虚拟串口）遥控平衡小车，并实时显示小车回传的
电压 / 倾角 / 轮速 / 姿态角 / PID 参数和波形。

## 目录结构

```
PC_Car_Controller/
├── car_controller.py     # 主程序（GUI + 串口 + 协议，单文件）
├── protocol_test.py      # 协议自检脚本（对照固件解析逻辑验证编码）
└── README.md             # 本说明
```

## 运行方法（无需安装任何第三方库）

1. 电脑装有 Python 3.8+（在 cmd 或 PowerShell 中验证：`python --version`）。
2. 双击或在命令行运行：

   ```
   python car_controller.py
   ```

3. 程序自动选择串口后端：
   - 已安装 `pyserial`（`pip install pyserial`）→ 使用 pyserial（支持 Windows / Linux / macOS）；
   - 未安装 → Windows 下自动改用系统 Win32 串口 API（ctypes），**零依赖**。
4. 点“刷新”选择串口（如 `COM3`），波特率默认 **9600**（与蓝牙模块/USART3 一致），点“连接串口”。

> ✅ 已在本项目内通过自检与冒烟测试：`python protocol_test.py`
> 会把控制端生成的每一帧喂入"固件 usart3.c v5.7 解析逻辑的镜像"，逐项比对一致。

## 硬件连接（两种方式任选）

**方式一：USB 转 TTL 直连（推荐，最简单）**
把 USB 转 TTL 模块与小车板 USART3 引脚相连（注意交叉连接 + 共地）：

| USB 转 TTL | 小车板 |
|---|---|
| TXD | PB11（USART3_RX） |
| RXD | PB10（USART3_TX） |
| GND | GND（必须共地） |

**方式二：PC 自带蓝牙直连（小车板载 HC-05/HC-06 类经典蓝牙模块）**

1. 小车**开机上电**，蓝牙模块进入通讯模式（若有 AT/通断开关，拨到"通/通讯"一侧；
   HC-05 的 KEY/EN 引脚悬空或接低为数据模式，板载模块通常默认即为数据模式）。
2. 电脑：设置 → 蓝牙和其他设备 → 添加设备 → 选择"蓝牙"。
   几秒后应出现以 `HC-05`（或 `WHEELTEC`、`BT04` 等）命名的设备 → 点击配对。
3. 提示输入 PIN 时输入 **1234**（HC-05/HC-06 出厂默认；部分模块为 0000）。
4. 配对成功后，设备管理器 → 端口(COM 和 LPT) 会出现
   **"蓝牙链接上的标准串行 (COMx)"**。回到控制终端点"刷新"，下拉框里选中该 COM
   （旁边会显示"蓝牙链接上的标准串行"字样），波特率 9600，连接。

   > 验证技巧：小车会**持续回传** `{A...}$` 数据帧。连上后如果"最近帧"开始刷新、
   > 电压/倾角显示数值，就说明连对了端口。

注意：
- 小车蓝牙模块**同一时刻只能被一台设备连接**。若之前与手机配对过，先在手机
  蓝牙设置里取消配对（或删除该设备），再与电脑配对；若仍失败，可把模块
  断电重启后再试。
- 电脑配对过一次后，该 COM 口会一直存在（即使小车关机），它是"配对记录"；
  小车开机后直接连接即可。
- 若搜索不到模块：确认小车已上电、模块处于通讯模式（非 AT 模式）、模块没被
  手机占用。
- 若模块是 BLE 型（HM-10/BT05 等，体积很小、一般没有 HC-05 那种金属屏蔽罩），
  Windows 不会生成可用 COM 口——这种情况请改用方式一（USB 转 TTL 直连）。

## 操作说明

| 操作 | 发送指令 | 说明 |
|---|---|---|
| 按住 `W` / `↑` 或按钮 | `A` (0x41) | 前进（持续发送，松开自动发 `Z` 刹车） |
| 按住 `S` / `↓` | `E` (0x45) | 后退 |
| 按住 `A` / `←` | `F` (0x46) | 左转（固件 F/G/H 均可） |
| 按住 `D` / `→` | `B` (0x42) | 右转（固件 B/C/D 均可） |
| 按住 `空格` / `Z` 或按钮 | `Z` (0x5A) | 刹车 / 停止 |
| 按一下 `X` | `X` (0x58) | 加速：Target_Velocity +100 |
| 按一下 `Y` | `Y` (0x59) | 减速：Target_Velocity -100 |
| 红色“紧急停车”按钮 | `Z`×3 | 连发三次刹车 |

- 方向键/方向盘按钮均为**按住持续发送、松开自动刹车**（与手机 APP 体验一致）。
- 连接成功后程序会先发送一次刹车，清掉小车残留的方向标志。
- 参数面板：输入值（0~9999）→ 点“设置”，通过参数帧写入；小车回传的 `{C...}$`
  帧会自动回填“当前”值和输入框。

## 通信协议（与固件 `MiniBalance_HARDWARE/USART3/usart3.c` 一一对应）

### 1. PC → 小车：单字节遥控指令（与蓝牙 APP 完全一致）

| 字节 | 固件处理 |
|---|---|
| `0x41` 'A' | 前：`Flag_front=1` |
| `0x45` 'E' | 后：`Flag_back=1` |
| `0x42`/`0x43`/`0x44` 'B'/'C'/'D' | 右转 |
| `0x46`/`0x47`/`0x48` 'F'/'G'/'H' | 左转 |
| `0x5A` 'Z' | 刹车：全部标志清零 |
| `0x58` 'X' | `Target_Velocity += 100`（每收到一帧 +100） |
| `0x59` 'Y' | `Target_Velocity -= 100` |
| 其他 > 0x0A 的字节 | 一律按刹车处理 |

### 2. PC → 小车：参数设置帧

```
0x7B | 参数编号('0'~'8') | '0' | 数值(ASCII 十进制) | 0x7D
```

| 编号 | 参数 |
|---|---|
| '0' | Target_Velocity |
| '1' | Balance_Kp |
| '2' | Balance_Kd |
| '3' | Velocity_Kp |
| '4' | Velocity_Ki |
| '5' | Turn_Kp |
| '6' | Turn_Kd |
| '7' | Distance_KP |
| '8' | Distance_KD |

例：`Balance_Kp = 42` → `7B 31 30 34 32 7D`。

> ⚠ **固件解析细节（重要）**：本固件（v5.7）的参数解析循环为
> `for(j=i; j>=4; j--) Data += (Receive[j-1]-48)*pow(10, i-j)`，帧尾不纳入计数。
> 逐字节推演结果表明：
> - 官方文档格式 `7B 编号 数值 7D` 不带前导 '0' 时并不精确：
>   发送 `25` 实际生效 `5`、发送 `100` 实际生效 `0`、发送 `5` 实际生效 `0`；
> - 本程序按 `7B 编号 '0' 数值 7D` 发送，任意位数（0~9999）均与固件解析结果**精确一致**
>   （已由 `protocol_test.py` 镜像验证）。

### 3. 读取参数帧（慎用）

```
7B 50 50 50 7D     → 固件 Receive[3]==0x50 → PID_Send=1 → 回传 {C...}$ 一帧
```

> ⚠ **已知固件问题**：触发读取成功后，固件参数解析器会停留在异常状态，之后发送的
> **参数设置帧将不再生效**（遥控单字节指令不受影响），需重新给小车断电上电恢复。
> 因此“读取全部参数”按钮在确认需要时再使用；遥控与参数设置都正常时不要点它。

### 4. 小车 → PC：回传帧（printf 输出，9600 波特，`$` 结尾）

| 帧 | 内容 |
|---|---|
| `{A<左轮速>:<右轮速>:<电压%>:<倾角°>}$` | 首页数据 |
| `{B<Pitch>:<Roll>:<Yaw>}$` | 姿态角（波形页） |
| `{C<9个PID参数>$` 依次为 TV, BKP, BKD, VKP, VKI, TKP, TKD, DKP, DKD | 调参页 |

## 常见问题

- **找不到串口 / 列表为空**：确认 USB 转 TTL 驱动已装（设备管理器 → 端口(COM 和 LPT)）；
  拔插后点“刷新”。蓝牙方式需先与 PC 配对成功。
- **连接失败**：端口被其他软件占用（关闭串口助手）；或选了手机蓝牙的 COM。
- **连上后小车没反应**：确认波特率为 9600、接线方向（TXD↔RX 交叉）与共地；
  先按一下 `Z` 确认日志出现 `TX 5A`。
- **按 X 没反应**：Target_Velocity 默认值有限幅（速度环 `Movement>2400` 截断），
  连续多次按 X 后速度已到上限；按 Y 可回退。
- **回传数据乱码**：波特率不是 9600，或接错成了 USART1（115200 的 ROS 口）。
